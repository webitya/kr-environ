# 2. MODULAR DEVELOPMENT PRINCIPLE

Build the website using a modular component architecture. Every major section should have its own reusable JSX component instead of writing the entire page inside a single file.

**Example:**

- `HomeHero.jsx`
- `HomeAbout.jsx`
- `HomeServices.jsx`
- `HomeProjects.jsx`
- `HomeGallery.jsx`
- `HomeVideos.jsx`
- `HomeBlog.jsx`
- `HomeContact.jsx`

Each page should assemble its components in the required order.

### Development rules

1. Keep page files responsible for arranging sections, not containing all UI markup.
2. Keep each major page section in a separate JSX component.
3. Create reusable components for buttons, headings, cards, forms, navigation, and footers.
4. Fetch dynamic content from the database through reusable data-access functions or server-side data-fetching modules.
5. Keep SEO metadata associated with each page and dynamic content type.
6. Use consistent naming conventions, imports, and folder organization.
7. Avoid unnecessary duplication of components across pages.
8. Components should be easy to maintain, test, and update independently.

# 4. HOMEPAGE MODULAR STRUCTURE

**Page URL:** `/`

**Page file:** `src/app/page.jsx`

Build the homepage by composing independent sections in this order:

1. `HomeHero.jsx` — Main headline, introduction, hero image, and primary CTA.
2. `HomeAbout.jsx` — Short company introduction and About Us link.
3. `HomeServices.jsx` — Featured services loaded from published database records.
4. `HomeWhyChooseUs.jsx` — Verified differentiators and reasons to work with the company.
5. `HomeExpertise.jsx` — Environmental consultancy and technical expertise.
6. `HomeProjects.jsx` — Selected published projects.
7. `HomeGallery.jsx` — Selected gallery images, linked to `/gallery/`.
8. `HomeVideos.jsx` — Featured videos with in-page playback.
9. `HomeBlog.jsx` — Latest published articles.
10. `HomeCTA.jsx` — Request a Consultation call to action.
11. `HomeContact.jsx` — Short contact information and enquiry entry point.

The homepage should import and arrange these components rather than implement each full section directly inside `page.jsx`.

**Dynamic content rule:** Services, projects, gallery items, videos, and blogs displayed on the homepage must come from the relevant data source. Hide sections that have no published content where appropriate.

**Services listing URL:** `/services/`

**Listing page file:** `src/app/services/page.jsx`

**Individual service URL pattern:** `/services/[slug]/`

**Dynamic detail page file:** `src/app/services/[slug]/page.jsx`

Components:

- `ServicesHero.jsx`
- `ServicesGrid.jsx`
- `ServiceCard.jsx`
- `ServiceDetailHero.jsx`
- `ServiceDetailContent.jsx`
- `ServiceBenefits.jsx`
- `ServiceProcess.jsx`
- `RelatedServices.jsx`
- `ServiceEnquiryCTA.jsx`

### Admin panel behaviour

When an administrator adds a service, the website should automatically generate a public URL from its unique slug.

Example:

- Title: Environmental Impact Assessment
- Slug: `environmental-impact-assessment`
- URL: `/services/environmental-impact-assessment/`

The same dynamic detail template must render all published services using the matching database record.

**Required service fields:**
- Title
- Slug
- Short description
- Full content
- Featured image
- Category
- SEO title
- Meta description
- Publication status

Include any additional technical or enquiry fields the actual service requires.

# 14. SEO AND ROUTE STRUCTURE

### Fixed pages

- `/`
- `/about-us/`
- `/our-expertise/`
- `/contact-us/`
- `/privacy-policy/`
- `/terms-and-conditions/`
- `/disclaimer/`

### Dynamic content pages

**Services**
- `/services/`
- `/services/[slug]/`

**Projects**
- `/projects/`
- `/projects/[slug]/`

**Blog**
- `/blog/`
- `/blog/[slug]/`
- `/blog/category/[slug]/`

### Fixed media pages

- `/gallery/`
- `/videos/`

### SEO rules

1. Generate metadata for each published service, project, and blog article.
2. Provide unique titles, meta descriptions, and canonical URLs.
3. Use readable, lowercase, hyphen-separated slugs.
4. Ensure slugs are unique within their corresponding content type.
5. Redirect old URLs if published slugs change.
6. Generate the XML sitemap from published, indexable pages.
7. Keep unpublished records out of public listings and search engine sitemaps.
8. Link relevant blog articles to services and relevant projects where appropriate.
9. Add breadcrumbs to nested service, project, and blog pages.
10. Avoid unnecessary indexable URLs for gallery and video filters.

# 15. ADMIN PANEL AND DATA MANAGEMENT

The admin panel must support:

**Services:** Create, edit, publish, unpublish, and delete service records.

**Blogs:** Create and manage articles, categories, slugs, images, and SEO metadata.

**Projects:** Manage project details, locations, images, categories, and public visibility.

**Gallery:** Upload images, add captions and alt text, assign categories, reorder, and hide content.

**Videos:** Add video URLs, thumbnails, descriptions, categories, and display order.

### Important development requirements

- Use database IDs as internal record identifiers.
- Use slugs only for service, project, and blog article detail routes.
- Validate all admin inputs on the server.
- Protect the admin panel with authentication and role-based authorization.
- Validate upload types and sizes.
- Prevent duplicate slugs.
- Use secure storage for uploaded media.
- Keep draft content private.
- Revalidate or refresh relevant pages after content changes.
- Generate public metadata only from the appropriate published content record.

---

# 16. FINAL DEVELOPMENT RULE

The KR Environ Solutions website must follow a modular component architecture.

The homepage should consist of separate files such as `HomeHero.jsx`, `HomeAbout.jsx`, `HomeServices.jsx`, `HomeProjects.jsx`, `HomeGallery.jsx`, `HomeVideos.jsx`, and `HomeBlog.jsx`.

Individual pages should be assembled from reusable components. Dynamic services, blog articles, and projects should use database-driven slug routes. Gallery and Videos should each have one fixed public page, with their items managed through the admin panel and displayed using filters, lightboxes, or embedded video players.

**Final objective:** A professional, SEO-friendly, responsive, database-driven website that is easy to maintain, scalable as content grows, and consistent with the KR Environ Solutions brand identity.
